# Final Year Project Documentation

## Purpose

This repository contains the documentation, research, decisions, requirements, development records, testing records, progress records, and supporting evidence for the final year software and electronics project.

The repository is used to maintain a traceable record of the project from initial ideas through development, testing, approved feature versions, and the final Master project.

## Project Traceability

The documentation system is designed to maintain the following chain:

Idea
? Research
? Requirement
? Decision
? Development
? Testing
? Evidence
? Verified Result
? Approved Feature Version
? Master

Not every project item will necessarily follow every stage.

---

## Approval Rules

Discussion does not constitute approval.

The project owner must explicitly approve:

- Feature Version contents
- Master contents
- Major project requirements
- Major committed design decisions
- Promotion of ideas into approved features
- Promotion of features into the Master

See [PROJECT_RULES.md](PROJECT_RULES.md) for the complete documentation rules.

---

## Git and Development

Git provides the history of changes to the project repositories.

Branches may be used for development work.

Commits record changes.

The documentation provides the explanation of what was done, why it was done, and what evidence supports it.

---

## Jira

Jira is used to manage planned project work.

The intended distinction is:

**Jira** — what needs to be done

**Git** — what changed

**Documentation** — what happened, why, and what evidence supports it

---

## Supervisor

Supervisor meetings, feedback, questions, and resulting actions can be recorded in the project documentation.

Supervisor oversight does not automatically constitute approval of project features or Master contents.
